# Event Collection

Консольное приложение для ведения личной коллекции посещенных мероприятий.

## Назначение

Event Collection — сервис для ведения личной коллекции посещенных мероприятий: концертов, спектаклей, выставок, фестивалей, спортивных матчей. Пользователь отмечает мероприятия, на которых побывал, ставит им оценки и в любой момент может посмотреть свою историю посещений. Приложение решает задачу хранения впечатлений: вместо разрозненных билетов, фотографий и заметок вся история собрана в одном месте.

## Целевая аудитория

Люди, которые регулярно посещают культурные, развлекательные и спортивные мероприятия и хотят вести личную историю посещений: любители концертов и театра, посетители выставок и фестивалей, болельщики, студенты.

## Предметная область

Досуг и культурно-массовые мероприятия. Мероприятие — событие с названием, категорией (концерт, спектакль, выставка, фестиваль, матч и т. д.) и датой проведения. Пользователь добавляет в свою коллекцию посещения уже состоявшихся мероприятий и оценивает каждое посещение по шкале от 1 до 5. По коллекции пользователь видит, на каких мероприятиях и когда он был и что ему понравилось.

## Возможности

- просмотр и поиск пользователей, добавление пользователя с проверкой email;
- просмотр мероприятий по дате, поиск по названию, добавление мероприятия;
- добавление посещения в коллекцию с проверкой, что мероприятие уже прошло и еще не добавлено;
- выставление оценки посещению по шкале от 1 до 5 с проверкой введенного значения;
- удаление посещения вместе с его оценкой;
- просмотр коллекции пользователя в виде карточек посещений;
- статистика: число пользователей, мероприятий и посещений, средняя оценка, категории.

## Основные классы

### User — пользователь

Атрибуты: `id`, `name`, `email`.

Методы:

- `from_data()` — создает пользователя из данных JSON (метод класса);
- `to_data()` — превращает пользователя в данные для JSON;
- `__str__()` — строковое представление: `1. Иван <ivan@example.com>`.

### Event — мероприятие

Атрибуты: `id`, `title`, `category`, `date`.

Методы:

- `is_past()` — проверяет, что мероприятие уже состоялось;
- `from_data()`, `to_data()` — JSON в объект и обратно;
- `__str__()` — `1. 05.09.2026 Фестиваль уличной еды (фестиваль)`.

### Visit — посещение

Атрибуты: `id`, `user` (объект `User`), `event` (объект `Event`), `rating` (объект `Rating` или `None`).

Методы:

- `rate()` — ставит посещению оценку: новую или вместо старой;
- `days_passed()` — сколько дней прошло с даты мероприятия;
- `card()` — карточка посещения для просмотра коллекции;
- `from_data()`, `to_data()` — JSON в объект и обратно, связи хранятся номерами;
- `__str__()` — `Посещение №1: Фестиваль уличной еды (фестиваль)`.

### Rating — оценка

Атрибуты: `id`, `score` (от 1 до 5).

Методы:

- `parse_score()` — превращает введенную строку в целое число (статический метод);
- `stars` — оценка звездами (свойство, пишется без скобок);
- `from_data()`, `to_data()` — JSON в объект и обратно;
- `__str__()` — `★★★★★ 5/5 — понравилось`.

## Взаимодействие объектов

```text
User ──┐
       ├──> Visit ──> Rating
Event ─┘
```

- `Visit` хранит ссылки на объекты `User` и `Event`, а не их номера, поэтому данные связанных объектов доступны прямо из посещения: `visit.user.name`, `visit.event.title`, `visit.event.date`.
- Оценка принадлежит посещению и лежит в атрибуте `visit.rating`. У одного посещения не может быть двух оценок: повторная оценка заменяет старую.
- Класс `Visit` использует метод `Event.is_past()`, когда проверяет, что мероприятие уже состоялось.
- В JSON связи хранятся номерами (`user_id`, `event_id`, `visit_id`). При загрузке номера превращаются обратно в ссылки на объекты, при сохранении — наоборот.

## Функции модулей

Операции с отдельным объектом реализованы методами классов, а работа с коллекциями объектов осталась функциями:

- `models/users.py` — `add_user`, `find_user_by_id`, `find_users`, `is_email_taken`, `sort_users`;
- `models/events.py` — `add_event`, `find_event_by_id`, `find_events`, `sort_events_by_date`, `get_categories`;
- `models/visits.py` — `add_visit`, `find_visit_by_id`, `has_visit`, `get_user_visits`, `remove_visit`, `collect_ratings`;
- `models/ratings.py` — `average_score`;
- `storage.py` — `load_json`, `save_json`, `load_users`, `save_users`, `load_events`, `save_events`, `load_visits`, `save_visits`, `load_ratings`, `save_ratings`;
- `utils.py` — `next_id`, `input_int`, `input_date`;
- `main.py` — `main`, `add_new_visit`.

## Структура проекта

- main.py – точка запуска, меню приложения;
- models/ – пакет с классами и функциями сущностей:
  - `__init__.py` – импорт классов из пакета: `from models import User, Event, Visit, Rating`;
  - users.py – класс `User` и функции работы с пользователями;
  - events.py – класс `Event` и функции работы с мероприятиями;
  - visits.py – класс `Visit` и функции работы с посещениями;
  - ratings.py – класс `Rating` и расчет средней оценки;
- storage.py – загрузка и сохранение данных: JSON в объекты и обратно;
- utils.py – вспомогательные функции;
- data/ – JSON-файлы данных;
- tests/ – автоматизированные тесты (по файлу на каждую сущность).

## Формат данных

Каждая сущность хранится в своем файле в папке `data/` в виде списка словарей. У каждой записи есть поле `id`, связи между сущностями задаются номерами:

| Файл | Пример записи |
|---|---|
| `users.json` | `{"id": 1, "name": "Иван", "email": "ivan@example.com"}` |
| `events.json` | `{"id": 1, "title": "Фестиваль уличной еды", "category": "фестиваль", "date": "2026-09-05"}` |
| `visits.json` | `{"id": 1, "user_id": 1, "event_id": 1}` |
| `ratings.json` | `{"id": 1, "visit_id": 1, "score": 5}` |

```bash

```

Тесты проверяют создание объектов `User`, `Event`, `Visit` и `Rating`, их атрибуты и методы, строковые представления, связь посещения с пользователем и мероприятием, правила добавления посещения и выставления оценки, а также функции работы с коллекциями.
