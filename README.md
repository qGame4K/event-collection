# Event Collection

Личная коллекция посещенных мероприятий: консольное приложение (ПР1–ПР3) и веб-интерфейс на Django (ПР5).

## Назначение

Event Collection — сервис для ведения личной коллекции посещенных мероприятий: концертов, спектаклей, выставок, фестивалей, спортивных матчей. Пользователь отмечает мероприятия, на которых побывал, ставит им оценки и в любой момент может посмотреть свою историю посещений. Приложение решает задачу хранения впечатлений: вместо разрозненных билетов, фотографий и заметок вся история собрана в одном месте.

## Используемые технологии

- Python 3;
- Django 5.2 — веб-фреймворк;
- HTML — разметка веб-страниц;
- CSS и Bootstrap 5.3 — оформление страниц;
- pytest — автоматизированные тесты;
- flake8 — проверка качества кода.

## Целевая аудитория

Люди, которые регулярно посещают культурные, развлекательные и спортивные мероприятия и хотят вести личную историю посещений: любители концертов и театра, посетители выставок и фестивалей, болельщики, студенты.

## Предметная область

Досуг и культурно-массовые мероприятия. Мероприятие — событие с названием, категорией (концерт, спектакль, выставка, фестиваль, матч и т. д.) и датой проведения. Пользователь добавляет в свою коллекцию посещения уже состоявшихся мероприятий и оценивает каждое посещение по шкале от 1 до 5.

## Основные классы

### User — пользователь

Атрибуты: `id`, `name`, `email`.

Методы:

- `from_data()` — создает пользователя из данных JSON (метод класса);
- `to_data()` — превращает пользователя в данные для JSON;
- `__str__()` — строковое представление: `1. Иван <ivan@example.com>`.

### Event — мероприятие

Атрибуты: `id`, `title`, `category`, `date`.

Методы:

- `is_past()` — проверяет, что мероприятие уже состоялось;
- `from_data()`, `to_data()` — JSON в объект и обратно;
- `__str__()` — `1. 05.09.2026 Фестиваль уличной еды (фестиваль)`.

### Visit — посещение

Атрибуты: `id`, `user` (объект `User`), `event` (объект `Event`), `rating` (объект `Rating` или `None`).

Методы:

- `rate()` — ставит посещению оценку: новую или вместо старой;
- `days_passed()` — сколько дней прошло с даты мероприятия;
- `card()` — карточка посещения для консольной версии;
- `from_data()`, `to_data()` — JSON в объект и обратно, связи хранятся номерами;
- `__str__()` — `Посещение №1: Фестиваль уличной еды (фестиваль)`.

### Rating — оценка

Атрибуты: `id`, `score` (от 1 до 5).

Методы:

- `parse_score()` — превращает введенную строку в целое число (статический метод);
- `stars` — оценка звездами (свойство, пишется без скобок);
- `from_data()`, `to_data()` — JSON в объект и обратно;
- `__str__()` — `★★★★★ 5/5 — понравилось`.

## Взаимодействие объектов

```text
User ──┐
       ├──> Visit ──> Rating
Event ─┘
```

- `Visit` хранит ссылки на объекты `User` и `Event`, поэтому данные связанных объектов доступны прямо из посещения: `visit.user.name`, `visit.event.title`, `visit.event.date`.
- Оценка принадлежит посещению и лежит в атрибуте `visit.rating`.
- В JSON связи хранятся номерами (`user_id`, `event_id`, `visit_id`). При загрузке номера превращаются в ссылки на объекты, при сохранении — наоборот.

## Страницы веб-интерфейса

| URL | Страница | View-функция |
|---|---|---|
| `/` | главная: описание приложения и навигация | `homepage.views.index()` |
| `/events/` | список мероприятий из `data/events.json` | `events.views.events()` |
| `/events/<int:event_id>/` | карточка мероприятия и признак «уже прошло» | `events.views.event_detail()` |
| `/visits/` | список посещений из `data/visits.json` | `visits.views.visits()` |
| `/visits/<int:visit_id>/` | карточка посещения: мероприятие, пользователь, оценка | `visits.views.visit_detail()` |

Если мероприятие или посещение с указанным номером не найдено, страница возвращается с кодом статуса 404. Страницы связаны навигацией: в шапке каждой страницы есть ссылки на главную, мероприятия и посещения.

Единый каркас страниц (кодировка, заголовок вкладки, Bootstrap 5.3, навигация) собирает функция `page()` в `homepage/views.py`. На следующей работе каркас станет Django-шаблоном.

## Структура проекта

- manage.py – запуск команд Django;
- eventcollection/ – конфигурация Django-проекта (`settings.py`, `urls.py`, `asgi.py`, `wsgi.py`);
- homepage/ – Django-приложение главной страницы: `views.py` (`page()`, `index()`), `urls.py`;
- events/ – Django-приложение мероприятий: `views.py` (`events()`, `event_detail()`), `urls.py`;
- visits/ – Django-приложение посещений: `views.py` (`visits()`, `visit_detail()`), `urls.py`;
- main.py – консольная версия приложения (сохранена с ПР3);
- models/ – классы предметной области и функции работы с ними;
- storage.py – загрузка и сохранение данных: JSON в объекты и обратно;
- utils.py – вспомогательные функции консольного ввода;
- data/ – JSON-файлы данных;
- tests/ – автоматизированные тесты (по файлу на каждую сущность).

Отдельное приложение для пользователей не создается: в Django уже есть встроенная модель `User`, работа с ней начнется в теме аутентификации.

## Функции модулей

- `models/users.py` — `add_user`, `find_user_by_id`, `find_users`, `is_email_taken`, `sort_users`;
- `models/events.py` — `add_event`, `find_event_by_id`, `find_events`, `sort_events_by_date`, `get_categories`;
- `models/visits.py` — `add_visit`, `find_visit_by_id`, `has_visit`, `get_user_visits`, `remove_visit`, `collect_ratings`;
- `models/ratings.py` — `average_score`;
- `storage.py` — `load_json`, `save_json`, `load_users`, `save_users`, `load_events`, `save_events`, `load_visits`, `save_visits`, `load_ratings`, `save_ratings`;
- `utils.py` — `next_id`, `input_int`, `input_date`;
- `main.py` — `main`, `add_new_visit`.

Веб-страницы используют функции ПР3: `load_events()`, `load_users()`, `load_visits()`, `load_ratings()`, `find_event_by_id()`, `find_visit_by_id()`, `sort_events_by_date()` и метод `Event.is_past()`. Операции, меняющие данные (добавление, оценка, удаление), пока доступны только в консольной версии: в вебе они появятся вместе с формами и POST-запросами.

## Формат данных

Каждая сущность хранится в своем файле в папке `data/` в виде списка словарей:

| Файл | Пример записи |
|---|---|
| `users.json` | `{"id": 1, "name": "Иван", "email": "ivan@example.com"}` |
| `events.json` | `{"id": 1, "title": "Фестиваль уличной еды", "category": "фестиваль", "date": "2026-09-05"}` |
| `visits.json` | `{"id": 1, "user_id": 1, "event_id": 1}` |
| `ratings.json` | `{"id": 1, "visit_id": 1, "score": 5}` |

## Текущее состояние и план развития

Реализовано на ПР5:

- Django-проект `eventcollection` и три приложения: `homepage`, `events`, `visits`;
- маршрутизация двух уровней: `urls.py` проекта подключает `urls.py` приложений;
- view-функции и пять страниц, включая динамические адреса с конвертером `<int:...>`;
- отображение данных предметной области из JSON через классы ПР3;
- навигация между страницами и оформление Bootstrap 5.3.

Планируется:

- перенос классов `User`, `Event`, `Visit` и `Rating` в Django ORM и подключение базы данных;
- переход на шаблоны Django вместо функции `page()`;
- формы для добавления мероприятий, посещений и оценок;
- регистрация и аутентификация пользователей;
- разработка API, контейнеризация, настройка CI/CD.
