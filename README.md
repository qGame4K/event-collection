# Event Collection

Личная коллекция посещенных мероприятий: консольное приложение (ПР1–ПР3) и веб-интерфейс на Django с шаблонами (ПР5–ПР6).

## Назначение

Event Collection — сервис для ведения личной коллекции посещенных мероприятий: концертов, спектаклей, выставок, фестивалей, спортивных матчей. Пользователь отмечает мероприятия, на которых побывал, ставит им оценки и в любой момент может посмотреть свою историю посещений.

## Используемые технологии

- Python 3;
- Django 5.2 — веб-фреймворк;
- Django Template Language (DTL) — шаблоны страниц;
- HTML5, CSS3, JavaScript;
- Bootstrap 5.3 — базовое оформление;
- JSON — хранение данных;
- pytest — автоматизированные тесты;
- flake8 — проверка качества кода.

## Целевая аудитория

Люди, которые регулярно посещают культурные, развлекательные и спортивные мероприятия и хотят вести личную историю посещений.

## Предметная область

Досуг и культурно-массовые мероприятия. Мероприятие — событие с названием, категорией и датой проведения. Пользователь добавляет в коллекцию посещения уже состоявшихся мероприятий и оценивает каждое посещение по шкале от 1 до 5.

## Основные классы

### User — пользователь

Атрибуты: `id`, `name`, `email`. Методы: `from_data()`, `to_data()`, `__str__()`.

### Event — мероприятие

Атрибуты: `id`, `title`, `category`, `date`. Методы: `is_past()`, `from_data()`, `to_data()`, `__str__()`.

### Visit — посещение

Атрибуты: `id`, `user` (объект `User`), `event` (объект `Event`), `rating` (объект `Rating` или `None`). Методы: `rate()`, `days_passed()`, `card()`, `from_data()`, `to_data()`, `__str__()`.

### Rating — оценка

Атрибуты: `id`, `score` (от 1 до 5). Методы: `parse_score()` (статический), `stars` (свойство), `from_data()`, `to_data()`, `__str__()`.

## Взаимодействие объектов

```text
User ──┐
       ├──> Visit ──> Rating
Event ─┘
```

`Visit` хранит ссылки на объекты `User` и `Event`, поэтому в шаблонах доступны `visit.user.name`, `visit.event.title`, `visit.event.date`. Оценка лежит в атрибуте `visit.rating`. В JSON связи хранятся номерами (`user_id`, `event_id`, `visit_id`).

## Веб-интерфейс

| URL | Страница | View-функция | Шаблон |
|---|---|---|---|
| `/` | главная: описание и навигация | `homepage.views.index()` | `homepage/index.html` |
| `/events/` | список мероприятий | `events.views.events()` | `events/event_list.html` |
| `/events/<int:event_id>/` | карточка мероприятия | `events.views.event_detail()` | `events/event_detail.html` |
| `/visits/` | список посещений | `visits.views.visits()` | `visits/visit_list.html` |
| `/visits/<int:visit_id>/` | карточка посещения | `visits.views.visit_detail()` | `visits/visit_detail.html` |

Если объекта с указанным номером нет, страница возвращается с кодом 404: во view проверяется результат поиска, а сообщение выводит шаблон через `{% if %}`.

HTML в Python-коде не формируется: функция `page()` из ПР5 удалена, все представления используют `render()`.

## Шаблоны Django

### Базовый шаблон и наследование

Общая структура страниц — в `templates/base.html`: объявление документа, кодировка, подключение Bootstrap и собственного CSS, логотип, навигация, контейнер содержимого, подвал и подключение JavaScript. Дочерние шаблоны наследуют его:

```text
{% extends "base.html" %}
{% block title %}...{% endblock %}
{% block content %}...{% endblock %}
```

### Включаемые шаблоны

Повторяющиеся фрагменты вынесены в отдельные файлы и подключаются тегом `{% include %}`:

- `templates/includes/navigation.html` — навигация, общая для всех страниц;
- `events/templates/events/includes/event_card.html` — карточка одного мероприятия;
- `visits/templates/visits/includes/visit_rating.html` — оценка посещения, используется и в списке, и на странице посещения.

### Контекст

Представления передают данные словарем контекста, например:

```text
context = {"events": sort_events_by_date(load_events(EVENTS_FILE))}
return render(request, "events/event_list.html", context)
```

В шаблоне данные доступны по именам ключей: `{% for event in events %}`, `{{ event.title }}`.

### Циклы и условия

- `{% for event in events %}` с веткой `{% empty %}` — на случай пустой коллекции;
- `{% if event %}` — карточка объекта или сообщение «не найдено»;
- `{% if passed %}` и `{% if visit.rating %}` — состояние мероприятия и наличие оценки.

### Фильтры

- `{{ events|length }}` — количество мероприятий;
- `{{ event.date|date:"d.m.Y" }}` — дата в привычном виде;
- `{{ event.title|default:"Без названия" }}` — значение по умолчанию.

### Именованные URL и пространства имён

В каждом приложении задано `app_name` (`homepage`, `events`, `visits`), маршруты названы `list` и `detail`. Ссылки в шаблонах формируются тегом `{% url %}`, жестко заданных адресов нет:

```text
{% url 'events:list' %}
{% url 'events:detail' event.id %}
{% url 'visits:detail' visit.id %}
```

## Статические файлы

Статика лежит в `homepage/static/homepage/`:

- `css/style.css` — собственные стили проекта (логотип, карточки мероприятий, оценка, подвал);
- `js/main.js` — подставляет текущий год в подвал страницы;
- `img/logo.png` — логотип проекта.

Подключение в `base.html` через `{% load static %}` и `{% static 'homepage/css/style.css' %}`.

## Структура проекта

- manage.py — запуск команд Django;
- eventcollection/ — настройки проекта (`settings.py`, `urls.py`);
- templates/ — шаблоны уровня проекта: `base.html`, `includes/navigation.html`;
- homepage/ — приложение главной страницы: `views.py`, `urls.py`, `templates/`, `static/`;
- events/ — приложение мероприятий: `views.py`, `urls.py`, `templates/events/`;
- visits/ — приложение посещений: `views.py`, `urls.py`, `templates/visits/`;
- models/ — классы предметной области `User`, `Event`, `Visit`, `Rating`;
- storage.py — загрузка и сохранение данных: JSON в объекты и обратно;
- utils.py — вспомогательные функции консольного ввода;
- main.py — консольная версия приложения (сохранена с ПР3);
- data/ — JSON-файлы данных;
- tests/ — автоматизированные тесты.

## Формат данных

| Файл | Пример записи |
|---|---|
| `users.json` | `{"id": 1, "name": "Иван", "email": "ivan@example.com"}` |
| `events.json` | `{"id": 1, "title": "Фестиваль уличной еды", "category": "фестиваль", "date": "2026-09-05"}` |
| `visits.json` | `{"id": 1, "user_id": 1, "event_id": 1}` |
| `ratings.json` | `{"id": 1, "visit_id": 1, "score": 5}` |

Данные загружаются функциями `storage.py` и превращаются в объекты классов из `models/`. Django ORM и база данных приложения пока не используются.
