# Event Collection

Консольное приложение для ведения личной коллекции посещенных мероприятий.

## Назначение

Event Collection — сервис для ведения личной коллекции посещенных мероприятий: концертов, спектаклей, выставок, фестивалей, спортивных матчей. Пользователь отмечает мероприятия, на которых побывал, ставит им оценки и в любой момент может посмотреть свою историю посещений. Приложение решает задачу хранения впечатлений: вместо разрозненных билетов, фотографий и заметок вся история собрана в одном месте.

## Целевая аудитория

Люди, которые регулярно посещают культурные, развлекательные и спортивные мероприятия и хотят вести личную историю посещений: любители концертов и театра, посетители выставок и фестивалей, болельщики, студенты.

## Предметная область

Досуг и культурно-массовые мероприятия. Мероприятие — событие с названием, категорией (концерт, спектакль, выставка, фестиваль, матч и т. д.) и датой проведения. Пользователь добавляет в свою коллекцию посещения уже состоявшихся мероприятий и оценивает каждое посещение по шкале от 1 до 5. По коллекции пользователь видит, на каких мероприятиях и когда он был и что ему понравилось.

## Основные сущности

- **Пользователь** — владелец личной коллекции (имя, email).
- **Мероприятие** — событие, которое можно посетить (название, категория, дата проведения).
- **Посещение** — запись в коллекции о том, что пользователь побывал на мероприятии (пользователь, мероприятие).
- **Оценка** — впечатление пользователя о посещении (балл от 1 до 5).

## Возможности

- просмотр и поиск пользователей, добавление пользователя с проверкой email;
- просмотр мероприятий по дате, поиск по названию, добавление мероприятия;
- добавление посещения в коллекцию с проверкой, что мероприятие уже прошло и еще не добавлено;
- выставление оценки посещению по шкале от 1 до 5 с проверкой введенного значения;
- удаление посещения вместе с его оценкой;
- просмотр коллекции пользователя в виде карточек посещений;
- статистика: число пользователей, мероприятий и посещений, средняя оценка, категории.

## Функции

**models/users.py** — пользователи:

- `add_user` — добавляет пользователя после проверки имени и email;
- `is_email_taken` — проверяет, занят ли email;
- `find_users` — ищет пользователей по части имени;
- `sort_users` — сортирует пользователей по имени;
- `format_user` — формирует строку с данными пользователя.

**models/events.py** — мероприятия:

- `add_event` — добавляет мероприятие после проверки названия;
- `is_past_event` — проверяет, что мероприятие уже состоялось;
- `find_events` — ищет мероприятия по части названия;
- `sort_events_by_date` — сортирует мероприятия по дате;
- `get_categories` — возвращает множество категорий мероприятий;
- `format_event` — формирует строку с данными мероприятия.

**models/visits.py** — посещения:

- `add_visit` — добавляет посещение, если мероприятие уже прошло и его нет в коллекции;
- `has_visit` — проверяет, есть ли мероприятие в коллекции пользователя;
- `get_user_visits` — возвращает посещения пользователя;
- `remove_visit` — удаляет посещение;
- `show_visit_card` — выводит карточку посещения: мероприятие, дата, сколько дней прошло, оценка.

**models/ratings.py** — оценки:

- `rate_event` — выставляет оценку посещению с проверкой ввода;
- `get_rating` — возвращает оценку посещения;
- `remove_rating` — удаляет оценку посещения;
- `average_score` — считает среднюю оценку;
- `format_score` — показывает оценку звездами с пояснением.

**storage.py** — `load_json`, `save_json`: загрузка и сохранение JSON-файлов.

**utils.py** — `next_id`, `find_by`, `input_int`, `input_date`: новый id, поиск записи по полю, безопасный ввод числа и даты.

## Структура проекта

- main.py – точка запуска, меню приложения;
- models/ – пакет с модулями сущностей:
  - users.py – работа с пользователями;
  - events.py – работа с мероприятиями;
  - visits.py – работа с посещениями;
  - ratings.py – работа с оценками;
- storage.py – сохранение и загрузка данных;
- utils.py – вспомогательные функции;
- data/ – JSON-файлы данных;
- tests/ – автоматизированные тесты (по файлу на каждую сущность).

## Формат данных

Каждая сущность хранится в своем файле в папке `data/` в виде списка словарей. У каждой записи есть поле `id`, связи между сущностями задаются идентификаторами:

| Файл | Пример записи |
|---|---|
| `users.json` | `{"id": 1, "name": "Иван", "email": "ivan@example.com"}` |
| `events.json` | `{"id": 1, "title": "Фестиваль уличной еды", "category": "фестиваль", "date": "2026-09-05"}` |
| `visits.json` | `{"id": 1, "user_id": 1, "event_id": 1}` |
| `ratings.json` | `{"id": 1, "visit_id": 1, "score": 5}` |
